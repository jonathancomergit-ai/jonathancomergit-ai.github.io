Big O: how work grows

Big O isn't about seconds. It answers one question: when the input gets bigger, how much more work does the code do? Double the list and the work might stay the same, double, quadruple... or explode.

Race the curves

Each line is how many steps that kind of code needs for an input of size n. Hit Grow n and watch them pull apart. Hover (or tap) the chart to read exact numbers. Tap a name to hide or show its line. O(2ⁿ) starts hidden because it squashes everything else flat. Turn it on and see.

Steps when n = 20

Log scale squeezes the tall numbers so every line fits: each gridline is 10× the one below. On a log scale O(2ⁿ) becomes a straight line, which is the giveaway that it's exponential.

How long would it really take?

Say your computer does a billion simple steps a second (about right for a modern one). Pick a size of input:

Big OSteps for n = Time

That's why it matters: at a million items, a good sort (n log n) finishes in a blink and a slow one (n²) takes minutes. Same computer, better idea.

The six you'll meet most

Fastest at the top. Each one has the code shape that gives it away.

O(1) · constant

Same work no matter how big the input. Ten items or ten million, one step.


            
Like opening a book at a page number you already know.

          

          

            
O(log n) · logarithmic

            
Cuts the problem in half every step. Doubling the input adds just one more step.

            

            
Finding a name in a phone book by opening it in the middle, again and again.

          

          

            
O(n) · linear

            
Looks at everything once. Twice the input, twice the work.

            

            
Checking every seat in a row for your lost phone.

          

          

            
O(n log n) · linearithmic

            
log n rounds of n work each. The speed limit for sorting by comparing.

            

            
Merge sort. Watch it split →

          

          

            
O(n²) · quadratic

            
Every item meets every other item. Twice the input, four times the work.

            

            
Everyone in a room shaking hands with everyone else. Bubble sort.

          

          

            
O(2ⁿ) · exponential

            
Each extra item doubles the work. Fine at 20, hopeless at 100.

            

            
Trying every possible combination, like every on/off setting of n switches.

          

        

      

    


    

      

        
Four rules for working it out

        

          

            
1. Drop the constants

            
3n and n grow the same way. Big O cares about the shape, not the exact count.

            

          

          

            
2. Keep the biggest term

            
n² + n: when n is huge, the n barely matters next to n².

            

          

          

            
3. Nested loops multiply

            
A loop inside a loop: outer count × inner count.

            

          

          

            
4. Back-to-back loops add

            
One loop, then another: add them, then apply rule 2.
