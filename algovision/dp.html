Dynamic programming: never solve the same thing twice

Big problems are often made of the same small problems, over and over. Dynamic programming solves each small one once, writes the answer in a table, and builds the big answer from the table. Watch the tables fill, then change the inputs and run it again.

    Spotting a DP problem
    
        
    
          
    
            
    1. Same small problems, again and again
    
            
    Naive fib(5) works out fib(2) three times. If you see repeats, a table can remember them.
    
          
    
          
    
            
    2. Big answer from small answers
    
            
    ways(square) comes from ways(above) and ways(left). Find that rule and you've found the DP.
    
          
    
          
    
            
    3. Define the cell
    
            
    Say in one sentence what a cell means: "dp[a] = fewest coins to make a". The rest follows.
    
          
    
          
    
            
    4. Fill in an order that works
    
            
    Every cell you read must already be filled. Usually small to big, top to bottom, left to right.
