Building this site from scratch

2026-09-09  ·  META  ·  3 min read

I have built a roguelike on an engine I wrote myself, trained neural networks to teach creatures to walk, and built a voice assistant that runs entirely offline in my house. Until today, none of that lived anywhere a person could actually look at it.

So: this. A place to put the work, and a place to write about it while it is still in progress rather than only once it is done.

Why hand-written HTML

The obvious move is a template — a themed static site generator, or one of the drag-and-drop portfolio builders. I went the other way, and the reason is boring but real: I want to be able to fix it in two years.

Every framework I could have picked has a version number attached to a clock. Plain HTML and CSS do not. There is no build step here, no node_modules, no dependency that goes stale while I am busy doing something else. Adding a post means copying a file and filling it in. That is the whole workflow, and it will still work when I have forgotten every detail of how the site is put together.

The best tool for a personal site is the one that still runs after you ignore it for a year.

The other reason is that I am learning this properly. I have been working through HTML structure from the bottom — what actually nests inside what, why <article> and <section> are different things — and there is no faster way to internalise that than having a real site whose layout breaks when you get it wrong.

The look

The palette is not invented. It is pulled straight off the Timeless title art — hot pink, electric cyan, amber — on near-black, with a faint drafting grid and CRT scanlines behind everything at an opacity you only notice if you go looking. It should feel like a game menu without actually pretending to be one.

Everything is driven by CSS custom properties in one block at the top of the stylesheet. Change one hex value there and the entire site changes colour. That was deliberate: I know I will want to repaint this once it has been live long enough to annoy me.

Where it lives, and where it is going

For now this is served by GitHub Pages, which is free, always up, and requires nothing of me beyond pushing a commit. That was the right first step — get it live, get a URL, stop it from existing only on my desktop.

The longer-term plan is more interesting. There is a TrueNAS box in my house that is already on twenty-four hours a day, and it can serve this site perfectly well. The catch is that self-hosting from a residential connection usually means port-forwarding to your home IP, which is a security problem and a dynamic-DNS problem at the same time.

The way around it is a Cloudflare Tunnel: the NAS opens an outbound connection to Cloudflare, visitors hit Cloudflare, and traffic comes back down that tunnel. No open ports, no exposed home IP, free TLS. The only thing I give up is uptime — the site becomes exactly as reliable as my power and my internet.

Which is fine, because the copy on GitHub is not going anywhere. Same files, two hosts, and I get to learn the self-hosting side on something where nothing breaks if I get it wrong.
